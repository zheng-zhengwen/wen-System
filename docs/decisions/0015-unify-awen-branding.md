# ADR-0015 · 全仓统一为 awen 品牌命名

- **日期**：2026-08-17
- **状态**：已采纳
- **依据**：2026-08-17 品牌统一任务

## 背景

工作台、内置 Agent、CLI、环境变量、API、持久化键和发布资产长期存在两套品牌标识。仅修改界面文字会让安装、升级、数据目录和服务发现继续依赖另一套名字，后续功能也容易重新引入混用。

## 决策

工作台统一使用 `awenops`，内置 Agent 统一使用 `awenAgent`，CLI 和用户目录统一使用 `awen` / `~/.awen`。代码标识按语言约定使用 `awen_agent`、`awenAgent` 或 `awen-agent`，环境变量使用 `AWENOPS_*` 和 `AWEN_AGENT_*`。

这次迁移覆盖源码、测试、API 路由、cookie、localStorage、数据目录、安装器、服务名、可执行文件、发布资产、文档和历史记录，不保留旧标识兼容层。

## 理由

- 单一命名降低跨前端、后端、CLI 和部署脚本的契约歧义。
- 保留兼容别名会违背彻底移除旧品牌的目标，并让后续扫描无法成为可靠门禁。
- 这是仍未正式发布的新命名，直接切换比长期维护双路迁移代码成本更低。

## 后果

- 原环境变量、cookie、本地存储键、数据目录、API 路由和服务名不再读取，部署方必须切换到新标识。
- 安装和更新依赖新的 `awenops` 与 `awen-agent` 发布仓库；发布仓库和资产就绪前，在线安装/更新会失败，而本地源码运行不受影响。
- 仓库测试与发布前扫描会同时检查文件内容和文件名，禁止旧品牌重新进入代码库。
