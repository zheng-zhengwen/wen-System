# ADR-0032：只保留琉璃·浅一个主题

- 状态：已采纳
- 日期：2026-09-03

## 背景

产品里长期并存多套主题和皮肤，分别由主题选择器、`data-theme`、`data-skin`、agents
子树的明暗判断、代码高亮、局部覆盖 CSS 和 `dark:` Tailwind 前缀共同维护。任何新增
界面都要同时检查浅色、深色和多套皮肤；漏掉一处时往往没有报错，只在某个子树或某个
状态里出现对比度、边框、背景或高亮不一致。

主题的真实使用者只需要一套稳定、可读、适配移动端的浅色界面。维护成本却摊在所有
后续功能和整站样式上。

## 决策

**只保留 `lucent-light`（琉璃·浅），删除其他主题、暗色分支和主题切换入口。**

- 主题注册表只保留一项，默认值就是 `lucent-light`。
- 旧 localStorage 里的历史主题一次性迁移到默认值，并写入迁移版本，避免反复覆盖用户
  后续可能保存的值。
- 删除旧主题 CSS 资源、`dark:` Tailwind 前缀、`.dark` 作用域和主题切换 UI。
- Listing 图片生成中的 `theme: light/dark/auto` 是图像设计的业务参数，不属于界面主题，
  因此保留。

## 理由

单主题不是砍掉功能，而是把“配色一致性”从每次开发都要靠人记忆的约定，收敛成一个
可测试的产品事实。这样后续界面只需要保证在琉璃·浅下正确；主题桥接、暗色 class、
皮肤覆盖和多套 token 之间的组合状态也随之消失。

保留 `data-theme` 选择器和迁移逻辑，是为了让启动路径、agents 子树和已有浏览器数据
仍有一条清晰的兼容路径；而不是把主题 id 硬编码散落到各处。

## 后果

- 新增界面不再需要维护深色分支，减少样式漂移和运行时样式覆盖。
- 旧用户刷新后会进入琉璃·浅；没有主题选择器，也没有暗色模式。
- 主题注册表、CSS 变量、默认主题和迁移逻辑由后端守卫测试钉住，未来如果重新引入主题，
  必须显式更新这些测试。
- 少量历史文档仍会提到早期多主题设计，它们描述的是当时的决策背景，不代表当前产品状态。
